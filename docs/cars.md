# รุ่นรถ รถรายคัน และหลายสาขา

`CarModel` เก็บสเปกร่วมของรุ่นย่อย/ปี/พวงมาลัย, `CarModelLocation` เก็บข้อเสนอของรุ่นในสาขาและผู้ให้บริการพร้อมราคา, `Car` เก็บทะเบียน สถานะ และ `locationId` ซึ่งเป็นตำแหน่งจริงล่าสุด ส่วน `Booking.carId` เป็นรถที่ระบบจัดสรรให้ทันทีเมื่อจอง

`Car.carModelLocationId` คือกลุ่มประจำการของรถ การคืนต่างสาขาเปลี่ยนตำแหน่งจริงโดยไม่เปลี่ยนกลุ่มประจำการ รถสามารถให้บริการที่ปลายทางได้เมื่อมีข้อเสนอเปิดบริการสำหรับรุ่นและผู้ให้บริการเดียวกันในประเทศเดียวกัน

## ย้ายข้อมูล

ฐานข้อมูลใหม่ใช้ `npm run db:migrate` เพื่อสร้าง schema จาก initial migration แล้วใช้ `npm run seed` เมื่อต้องการข้อมูลตัวอย่าง

ฐานข้อมูลที่ใช้ migration ชุดเดิมครบทั้ง 5 ไฟล์แล้วใช้ `npm run db:migrate` เพื่อบันทึก initial migration ใน `schema_migrations` หลังตรวจสอบ schema และ checksum ของประวัติเดิม ฐานข้อมูลที่มี schema สุดท้ายและยังไม่มีประวัติสามารถใช้คำสั่งเดียวกันได้

หากฐานข้อมูลยังรัน migration ชุดเดิมไม่ครบ ให้รัน migration จาก backend ก่อนรวมไฟล์ (commit `28372c7`) จนครบก่อนใช้รุ่นนี้ สำหรับฐานข้อมูลในเครื่อง ใช้คำสั่งต่อไปนี้จาก backend รุ่นเดิมเพื่อสำรองและตรวจสอบข้อมูลรถและรายการจองระหว่างอัปเกรด

```sh
npm run db:migrate:cars
```

คำสั่งสำรองรถและการจองลง `backups/` ซึ่งไม่เข้า Git แล้วรัน migration พร้อมตรวจเทียบฟิลด์เดิม ไฟล์มีข้อมูลรายการจอง ควรเก็บไว้ในเครื่องที่ได้รับอนุญาตและจัดการตามนโยบายสำรองข้อมูล

ฟิลด์สเปกและราคาบน `Car` ยังเก็บเป็น compatibility mirror สำหรับ API เดิม การอ่านหลักใช้ model/offer ส่วนการเขียนผ่าน API จะปรับ mirror ภายใน transaction เดียวกัน ยังไม่ควรลบคอลัมน์เหล่านี้จนกว่าจะยกเลิก clients เดิมทั้งหมด

รูปของรุ่นรถเก็บที่ `CarModel.imageUrl` หากกำลังอัปเกรดฐานข้อมูลรุ่นเก่าที่มี URL ของรถรายคันต่างจากรุ่นหรือยังไม่มีรุ่นที่เชื่อมโยง ให้จัดการข้อมูลรูปก่อนรัน migration ชุดเดิมจนจบ

## API

| Endpoint | การใช้งาน |
| --- | --- |
| `GET /api/cars/search` | ค้นหาข้อเสนอและจำนวนรถว่าง รับ `country`, `locationId`, `dropoffLocationId`, `startDateTime`, `endDateTime` เวลาเป็น ISO พร้อม offset; เมื่อส่งช่วงเวลาต้องส่งทั้งคู่ |
| `GET /api/cars/catalog` | แอดมินดูรุ่น ข้อเสนอ และจำนวนรถประจำกลุ่ม |
| `POST /api/cars/models`, `PATCH /api/cars/models/:id` | สร้าง/แก้ไขสเปกรุ่น การแก้สเปกถูกกันเมื่อมีรายการจองค้าง |
| `POST /api/cars/offers`, `PATCH /api/cars/offers/:id` | เปิดบริการรายสาขา/แก้ราคา สถานะ และเวลาเตรียมรถ รุ่น สาขา และผู้ให้บริการของข้อเสนอเดิมเปลี่ยนไม่ได้ |
| `POST /api/cars`, `PATCH /api/cars/:id` | รับข้อมูลได้สองแบบ ส่ง `carModelLocationId` พร้อมทะเบียน ปี และสถานะเพื่อใช้ข้อเสนอรายสาขา หรือส่งข้อมูลสเปกและราคาทั้งชุดตามรูปแบบเดิม ส่ง `transfer: true` กับแบบแรกเพื่อย้ายตำแหน่งจริงไปสาขาที่เลือก |
| `POST /api/cars/bulk` | เพิ่มหลายทะเบียนให้รุ่นและสาขาเดียวกัน สูงสุด 100 คันใน transaction เดียว หากทะเบียนซ้ำจะไม่บันทึกทั้งชุด |
| `GET /api/cars/:id/schedule` | แอดมินดูรายการจองและประวัติการย้ายรถ |
| `POST /api/bookings/calculate`, `POST /api/bookings` | ส่ง `carModelLocationId` เพื่อเลือกรุ่น/สาขา หรือ `carId` สำหรับ client เดิม โดยส่งอย่างใดอย่างหนึ่ง |
| `PATCH /api/bookings/:id/status` | เปลี่ยนสถานะพร้อมตรวจตารางรถและบันทึกการคืนรถ |

การจองส่ง `quotedTotal` ได้ เมื่อราคาเปลี่ยนจากยอดที่ลูกค้าตรวจสอบ ระบบคืน 409 `PRICE_CHANGED` เพื่อให้ยืนยันราคาใหม่ ค่าเงินในข้อเสนอใหม่ยังเป็น THB ตามระบบเดิม

## ความว่างและการคืนต่างสาขา

- นับเฉพาะรถที่เปิดบริการ และว่างตลอดช่วงเวลาที่ต้องการ รถคันเดียวต้องรองรับทั้งช่วงเช่า
- PENDING และ APPROVED กันรถ ไม่ปล่อย PENDING อัตโนมัติ แอดมินต้องยกเลิก/ปฏิเสธเพื่อคืนความว่าง
- จำลองลำดับการจองจากตำแหน่งจริงล่าสุด โดยแต่ละทริปต้องเริ่มที่สาขาที่รถอยู่และเว้น `turnaroundMinutes` หลังคืน
- การแทรกหรือยกเลิกทริปต้องไม่ทำให้สาขารับของทริปถัดไปผิดตำแหน่ง หากมีรายการพึ่งพาต้องจัดการรายการถัดไปก่อน
- รุ่นและผู้ให้บริการต้องเปิดบริการที่สาขาคืน และรับคืนภายในประเทศเดียวกัน
- เวลารับและคืนแปลงจากเขตเวลาของแต่ละสาขาเป็น UTC แยกกัน เกณฑ์ราคาหลัง 14:00 ยังอิงเขตเวลาสาขารับรถตามพฤติกรรมเดิม
- การยืนยัน COMPLETED ทำได้หลังเวลาคืนของรายการ APPROVED บันทึก `CarMovement` เปลี่ยนตำแหน่งจริง และเริ่มเวลาเตรียมรถจากเวลาที่รับคืนจริง หากจะกระทบการจองถัดไปต้องจัดการตารางก่อนยืนยัน
- COMPLETED ย้อนกลับไม่ได้ การส่งสถานะเดิมซ้ำไม่สร้างประวัติย้ายรถซ้ำ
- การย้ายรถหรือเปลี่ยนกลุ่มประจำการถูกกันขณะมี PENDING/APPROVED
- Booking เก็บราคา เวลาเตรียมรถ และข้อมูลรุ่น/ทะเบียน/สถานที่ ณ วันจองแยกจากข้อมูลปัจจุบัน รายการเก่าที่ backfill จะได้ snapshot ตามข้อมูลที่มีอยู่ตอนย้าย เพราะระบบเก่าไม่ได้บันทึกสเปกย้อนหลังไว้

การแก้ inventory และตารางรถใช้ transaction advisory lock ร่วมกัน และล็อกแถวรถเพื่อตรวจซ้ำก่อนจัดสรร จึงกันการแข่งขันข้ามข้อเสนอและการแก้สถานะได้ การค้นหาไม่ล็อกและต้องตรวจซ้ำเมื่อจอง สำหรับปริมาณงานสูงควรเปลี่ยนเป็น lock ตามกลุ่มรุ่น/ผู้ให้บริการด้วยลำดับ lock ที่แน่นอน

ค่าเตรียมรถของข้อมูลเดิมเป็น 0 นาทีเพื่อคงพฤติกรรมการจองติดกัน ข้อเสนอใหม่เริ่มที่ 60 นาทีและแอดมินปรับได้

## ตรวจสอบ

```sh
npm run build
npm run test:cars
```

`test:cars` สร้าง schema ชั่วคราวบน PostgreSQL ในเครื่อง ทดสอบการรัน seed ซ้ำ รันชุดทดสอบทั้งหมด และลบ schema ชั่วคราวเมื่อจบ ใช้ `npm run test:cars -- --legacy` เพื่อทดสอบการรับประวัติจาก migration ชุดเดิมและตรวจว่าข้อมูลรถเดิมยังอยู่

หน้าแอดมิน `/admin/cars` รวมการจัดการรุ่น บริการรายสาขา และทะเบียนรถ มีสามมุมมอง: ตามรุ่นรถ, ตามสาขา และทะเบียนทั้งหมด ใช้ `?view=inventory` สำหรับมุมมองทะเบียนทั้งหมด ตารางรถยังใช้อนุมัติ ยกเลิก รับคืน หรือเปิดคำขออีกครั้งได้

## เพิ่มหลายคันและดูยอดต่อ location

ใน `/admin/cars` กด “เพิ่มรถลงสาขา” หรือเพิ่มจากการ์ดรุ่น/สาขา แล้วเลือก “เพิ่มหลายทะเบียนในครั้งเดียว” เพื่อกรอกทะเบียนบรรทัดละคัน แต่ละทะเบียนสร้าง `Car` คนละแถวและมีตารางจองแยกกัน ข้อมูลสีและเลขไมล์ที่กรอกใช้ร่วมทั้งชุด ส่วน VIN บันทึกแยกได้ในฟอร์มรายคัน

ตัวอย่าง request:

```json
{
  "carModelLocationId": "offer-id",
  "year": 2024,
  "isAvailable": true,
  "licensePlates": ["DEMO-001", "DEMO-002", "DEMO-003"]
}
```

`GET /api/cars/catalog` แสดง `models[].totalCars` และ `locationCount` สำหรับแต่ละรุ่น, `offers[].inventoryCount` สำหรับรุ่น/ผู้ให้บริการที่อยู่ในสาขานั้นจริง และ `locationInventory` สำหรับรถทุกรุ่นที่อยู่ใน location เดียวกัน จำนวนเปิดให้เช่าแสดงสถานะบริการ หากต้องการยืนยันความว่างในช่วงเวลาให้ใช้ API ค้นหา

## หน้าจัดการรถ V2

Initial migration สร้าง `Car.exteriorColor`, `odometerKm`, `vin`, `operationalStatus` และ `CarMovement.note` รถที่ไม่มีรายละเอียดแสดง “—” และรถที่ปิดบริการจากการย้ายข้อมูลรุ่นเก่ามีสถานะ `INACTIVE`

`GET /api/cars/catalog` ส่ง `models`, `offers`, `locationInventory`, `units`, `summary` และ `generatedAt` จาก repeatable-read transaction เดียวกัน `units[].homeLocationId` คือสาขาประจำกลุ่ม ส่วน `locationId` คือตำแหน่งจริงหลังคืนรถ ราคาที่แสดงในหน่วยรถอ้างอิงข้อเสนอในตำแหน่งปัจจุบันเมื่อมี และมุมมองรุ่นจะแสดงข้อเสนอราคาแยกกัน แต่ละกลุ่มสาขา/ผู้ให้บริการแสดงทะเบียนเพียงครั้งเดียวแม้มีหลายข้อเสนอ

`operationalStatus` มี `AVAILABLE`, `CLEANING`, `MAINTENANCE`, `INACTIVE` เมื่อส่งสถานะนี้ต้องส่ง `isAvailable` ให้ตรงกัน (`true` เฉพาะ `AVAILABLE`) API เดิมที่ส่งเพียง `isAvailable` ยังใช้ได้ และการบันทึก `false` ซ้ำจะคงเหตุผลปิดบริการเดิมไว้ การปิดบริการรถที่ยังเปิดอยู่ถูกกันเมื่อมีรายการจองค้าง

`inventoryStatus` เป็นสถานะที่คำนวณเพิ่มสำหรับหน้าจอ ได้แก่สถานะปฏิบัติงานข้างต้น, `RESERVED`, `IN_USE`, `OVERDUE`, `UNASSIGNED` รวมการรอ `availableFrom` หลังคืนรถ การปิดรับจองของสาขา และรายการจองที่ยังไม่สิ้นสุดจริง รถเกินกำหนดคืนไม่ถูกจัดสรรใหม่จนกว่าจะจัดการรายการเดิม

KPI ด้านบนเป็นยอดทั้งระบบ ส่วนจำนวนในแท็บ/ผลลัพธ์เป็นยอดหลังกรอง ตัวกรองและมุมมองอยู่ใน query string เพื่อให้ refresh และ Back กลับมาที่บริบทเดิม CSV ส่งออกทะเบียนที่ตรงกับตัวกรองทั้งหมด

การย้ายสาขาใช้ `PATCH /api/cars/:id` พร้อม `transfer: true` และ `transferNote` (optional, สูงสุด 1,000 ตัวอักษร) ปลายทางต้องเปิดบริการสำหรับรุ่นและผู้ให้บริการเดียวกันภายในประเทศเดียวกัน และรถต้องไม่มี `PENDING`/`APPROVED` เหตุผลถูกบันทึกในประวัติการย้ายรถ การแก้ข้อมูลรถตามปกติไม่ย้ายตำแหน่งจริงที่เกิดจากการคืนต่างสาขา

ข้อมูลตัวอย่างมีรถ **134 คันใน 28 รุ่น** กระจายครบ **13 locations** ทุกรุ่นมีอย่างน้อย 3 คัน และทุก location มีหลายคัน รุ่นในประเทศที่มีหลายสาขามีรถกระจายข้ามสาขาด้วย ทะเบียนตัวอย่างขึ้นต้น `DEMO-` และใช้ ID คงที่

สำหรับข้อมูลตัวอย่างเดิมที่มี 28 คัน ใช้คำสั่งนี้เพื่อเพิ่มเฉพาะรถและข้อเสนอที่ยังขาด โดยเก็บทะเบียน ตำแหน่ง สถานะ และรายการจองเดิมทั้งหมดไว้:

```sh
npm run seed:cars -- --dry-run
npm run seed:cars
```

คำสั่งนี้ไม่สร้างบัญชีหรือแก้รถเดิม รันซ้ำได้โดยไม่เพิ่มข้อมูลซ้ำ ส่วนการ seed ฐานข้อมูลใหม่ด้วย `npm run seed` จะสร้างชุดรถหลายคันนี้ด้วย
