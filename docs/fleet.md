# รุ่นรถ รถรายคัน และหลายสาขา

`CarModel` เก็บสเปกร่วมของรุ่นย่อย/ปี/พวงมาลัย, `CarModelLocation` เก็บข้อเสนอของรุ่นในสาขาและผู้ให้บริการพร้อมราคา, `Car` เก็บทะเบียน สถานะ และ `locationId` ซึ่งเป็นตำแหน่งจริงล่าสุด ส่วน `Booking.carId` เป็นรถที่ระบบจัดสรรให้ทันทีเมื่อจอง

`Car.carModelLocationId` คือกลุ่มประจำการของรถ การคืนต่างสาขาเปลี่ยนตำแหน่งจริงโดยไม่เปลี่ยนกลุ่มประจำการ รถสามารถให้บริการที่ปลายทางได้เมื่อมีข้อเสนอเปิดบริการสำหรับรุ่นและผู้ให้บริการเดียวกันในประเทศเดียวกัน

## ย้ายข้อมูล

Migration `20261117000000_model_fleet_locations` เป็นการเพิ่มโครงสร้างและ backfill โดยรักษา ID รถและ booking รวมทั้งทุกฟิลด์เดิมไว้ รุ่นจะถูกรวมเมื่อข้อมูลสเปกและข้อมูลที่แสดงตรงกันทั้งหมด ราคาหรือผู้ให้บริการต่างกันสร้างข้อเสนอแยก รถที่ไม่มี location ยังเก็บไว้แต่ไม่ปรากฏในการค้นหารุ่นจนกว่าแอดมินจะจัดสาขา

สำหรับฐานข้อมูลในเครื่องที่ใช้ migrations เดิมแล้ว:

```sh
npm run prisma:generate
npm run prisma:fleet:migrate
```

คำสั่งหลังสำรองรถและการจองลง `backups/` ซึ่งไม่เข้า Git แล้วรัน migration พร้อมตรวจเทียบทุกฟิลด์เดิม ไฟล์มีข้อมูลรายการจอง ควรเก็บไว้ในเครื่องที่ได้รับอนุญาตและจัดการตามนโยบายสำรองข้อมูล

ฐานข้อมูลใหม่ใช้ `npm run prisma:deploy` แล้ว seed ได้ตามปกติ การ deploy ใช้ migration เพื่อให้เกิด backfill อย่าใช้ `prisma db push` แทน migration นี้ หากฐานข้อมูลเก่าถูกสร้างด้วย db push และยังไม่มี migration history ต้องตรวจ schema และ baseline migrations เดิมก่อน deploy โดยไม่ reset ข้อมูล

ฟิลด์สเปกและราคาบน `Car` ยังเก็บเป็น compatibility mirror สำหรับ API เดิม การอ่านหลักใช้ model/offer ส่วนการเขียนผ่าน API จะปรับ mirror ภายใน transaction เดียวกัน ยังไม่ควรลบคอลัมน์เหล่านี้จนกว่าจะยกเลิก clients เดิมทั้งหมด

รูปของรุ่นรถเก็บที่ `CarModel.imageUrl` หลัง migration `20261118000000_drop_car_image_url` ฐานข้อมูลที่มี URL รายคันต่างจากรุ่นหรือยังไม่มีรุ่นที่เชื่อมโยงต้องจัดการข้อมูลรูปก่อนรัน migration เพื่อรักษารูปเดิมไว้

## API

| Endpoint | การใช้งาน |
| --- | --- |
| `GET /api/fleet/search` | ค้นหาข้อเสนอและจำนวนรถว่าง รับ `country`, `locationId`, `dropoffLocationId`, `startDateTime`, `endDateTime` เวลาเป็น ISO พร้อม offset; เมื่อส่งช่วงเวลาต้องส่งทั้งคู่ |
| `GET /api/fleet/catalog` | แอดมินดูรุ่น ข้อเสนอ และจำนวนรถประจำกลุ่ม |
| `POST /api/fleet/models`, `PATCH /api/fleet/models/:id` | สร้าง/แก้ไขสเปกรุ่น การแก้สเปกถูกกันเมื่อมีรายการจองค้าง |
| `POST /api/fleet/offers`, `PATCH /api/fleet/offers/:id` | เปิดบริการรายสาขา/แก้ราคา สถานะ และเวลาเตรียมรถ รุ่น สาขา และผู้ให้บริการของข้อเสนอเดิมเปลี่ยนไม่ได้ |
| `POST /api/fleet/cars`, `PATCH /api/fleet/cars/:id` | เพิ่ม/แก้ทะเบียน เลือกกลุ่มประจำการ ปี และสถานะ ส่ง `transfer: true` เพื่อย้ายตำแหน่งจริงไปสาขาที่เลือกอย่างชัดเจน |
| `POST /api/fleet/cars/bulk` | เพิ่มหลายทะเบียนให้รุ่นและสาขาเดียวกัน สูงสุด 100 คันใน transaction เดียว หากทะเบียนซ้ำจะไม่บันทึกทั้งชุด |
| `GET /api/fleet/cars/:id/schedule` | แอดมินดูรายการจองและประวัติการย้ายรถ |
| `POST /api/bookings/calculate`, `POST /api/bookings` | ส่ง `carModelLocationId` เพื่อเลือกรุ่น/สาขา หรือ `carId` สำหรับ client เดิม โดยส่งอย่างใดอย่างหนึ่ง |
| `PATCH /api/bookings/:id/status` | เปลี่ยนสถานะพร้อมตรวจตารางรถและบันทึกการคืนรถ |

การจองส่ง `quotedTotal` ได้ เมื่อราคาเปลี่ยนจากยอดที่ลูกค้าตรวจสอบ ระบบคืน 409 `PRICE_CHANGED` เพื่อให้ยืนยันราคาใหม่ ค่าเงินในข้อเสนอใหม่ยังเป็น THB ตามระบบเดิม

## ความว่างและการคืนต่างสาขา

- นับเฉพาะรถที่เปิดบริการ และว่างตลอดช่วงเวลาที่ต้องการ รถคันเดียวต้องรองรับทั้งช่วงเช่า
- PENDING และ APPROVED กันรถ ไม่ปล่อย PENDING อัตโนมัติ แอดมินต้องยกเลิก/ปฏิเสธเพื่อคืนความว่าง
- จำลองลำดับการจองจากตำแหน่งจริงล่าสุด โดยแต่ละทริปต้องเริ่มที่สาขาที่รถอยู่และเว้น `turnaroundMinutes` หลังคืน
- การแทรกหรือยกเลิกทริปต้องไม่ทำให้สาขารับของทริปถัดไปผิดตำแหน่ง หากมีรายการพึ่งพาต้องจัดการรายการถัดไปก่อน
- รุ่นและผู้ให้บริการต้องเปิดบริการที่สาขาคืน และรับคืนภายในประเทศเดียวกัน
- เวลารับและคืนแปลงจากเขตเวลาของแต่ละสาขาเป็น UTC แยกกัน เกณฑ์ราคาหลัง 14:00 ยังอิงเขตเวลาสาขารับรถตามพฤติกรรมเดิม
- การยืนยัน COMPLETED ทำได้หลังเวลาคืนของรายการ APPROVED บันทึก `CarMovement` เปลี่ยนตำแหน่งจริง และเริ่มเวลาเตรียมรถจากเวลาที่รับคืนจริง หากจะกระทบการจองถัดไปต้องจัดการตารางก่อนยืนยัน
- COMPLETED ย้อนกลับไม่ได้ การส่งสถานะเดิมซ้ำไม่สร้างประวัติย้ายรถซ้ำ
- การย้ายรถหรือเปลี่ยนกลุ่มประจำการถูกกันขณะมี PENDING/APPROVED
- Booking เก็บราคา เวลาเตรียมรถ และข้อมูลรุ่น/ทะเบียน/สถานที่ ณ วันจองแยกจากข้อมูลปัจจุบัน รายการเก่าที่ backfill จะได้ snapshot ตามข้อมูลที่มีอยู่ตอนย้าย เพราะระบบเก่าไม่ได้บันทึกสเปกย้อนหลังไว้

การแก้ inventory และตารางรถใช้ transaction advisory lock ร่วมกัน และล็อกแถวรถเพื่อตรวจซ้ำก่อนจัดสรร จึงกันการแข่งขันข้ามข้อเสนอและการแก้สถานะได้ การค้นหาไม่ล็อกและต้องตรวจซ้ำเมื่อจอง สำหรับปริมาณงานสูงควรเปลี่ยนเป็น lock ตามกลุ่มรุ่น/ผู้ให้บริการด้วยลำดับ lock ที่แน่นอน

ค่าเตรียมรถของข้อมูลเดิมเป็น 0 นาทีเพื่อคงพฤติกรรมการจองติดกัน ข้อเสนอใหม่เริ่มที่ 60 นาทีและแอดมินปรับได้

## ตรวจสอบ

```sh
npm run build
npm run test:fleet
```

`test:fleet` ใช้ PostgreSQL ในเครื่อง สร้าง schema ชั่วคราวที่ชื่อสุ่ม ทดสอบย้ายข้อมูลจาก schema เดิม ตรวจราคา/ทะเบียน/booking/รุ่นต่างพวงมาลัย ทดสอบ seed ซ้ำ แล้วรัน tests ทั้งหมดด้วยฐานข้อมูลแยก ลบเฉพาะ schema ชั่วคราวเมื่อจบ

หน้าแอดมิน `/admin/cars` รวมการจัดการรุ่น บริการรายสาขา และทะเบียนรถ มีสามมุมมอง: ตามรุ่นรถ, ตามสาขา และทะเบียนทั้งหมด หน้า `/admin/fleet` เดิม redirect ไป `/admin/cars?view=model` ตารางรถยังใช้อนุมัติ ยกเลิก รับคืน หรือเปิดคำขออีกครั้งได้

## เพิ่มหลายคันและดูยอดต่อ location

ใน `/admin/cars` กด “เพิ่มรถลงสาขา” หรือเพิ่มจากการ์ดรุ่น/สาขา แล้วเลือก “เพิ่มหลายทะเบียนในครั้งเดียว” เพื่อกรอกทะเบียนบรรทัดละคัน แต่ละทะเบียนสร้าง `Car` คนละแถวและมีตารางจองแยกกัน ข้อมูลสีและเลขไมล์ที่กรอกใช้ร่วมทั้งชุด ส่วน VIN บันทึกแยกได้ในฟอร์มรายคัน

ตัวอย่าง request:

```json
{
  "carModelLocationId": "offer-id",
  "year": 2024,
  "isAvailable": true,
  "licensePlates": ["DEMO-001", "DEMO-002", "DEMO-003"]
}
```

`GET /api/fleet/catalog` แสดง `models[].totalCars` และ `locationCount` สำหรับแต่ละรุ่น, `offers[].inventoryCount` สำหรับรุ่น/ผู้ให้บริการที่อยู่ในสาขานั้นจริง และ `locationInventory` สำหรับรถทุกรุ่นที่อยู่ใน location เดียวกัน จำนวนเปิดให้เช่าเป็นสถานะบริการ ไม่ใช่การยืนยันความว่างในช่วงวันที่ต้องการ

## หน้าจัดการรถ V2

Migration `20261117010000_admin_fleet_v2` เพิ่ม `Car.exteriorColor`, `odometerKm`, `vin`, `operationalStatus` และ `CarMovement.note` รถเก่าที่ไม่มีรายละเอียดแสดง “—”; รถที่ปิดบริการเดิมได้สถานะ `INACTIVE` เพราะไม่มีข้อมูลยืนยันว่าอยู่ระหว่างซ่อม

`GET /api/fleet/catalog` เพิ่ม `units`, `summary`, `generatedAt` โดยอ่านด้วย repeatable-read transaction เดียวกัน ยังคงฟิลด์ตอบกลับเดิมทั้งหมด `units[].homeLocationId` คือสาขาประจำกลุ่ม ส่วน `locationId` คือตำแหน่งจริงหลังคืนรถ ราคาที่แสดงในหน่วยรถอ้างอิงข้อเสนอในตำแหน่งปัจจุบันเมื่อมี และมุมมองรุ่นจะแสดงข้อเสนอราคาแยกกัน แต่ละกลุ่มสาขา/ผู้ให้บริการแสดงทะเบียนเพียงครั้งเดียวแม้มีหลายข้อเสนอ

`operationalStatus` มี `AVAILABLE`, `CLEANING`, `MAINTENANCE`, `INACTIVE` เมื่อส่งสถานะนี้ต้องส่ง `isAvailable` ให้ตรงกัน (`true` เฉพาะ `AVAILABLE`) API เดิมที่ส่งเพียง `isAvailable` ยังใช้ได้ และการบันทึก `false` ซ้ำจะคงเหตุผลปิดบริการเดิมไว้ การปิดบริการรถที่ยังเปิดอยู่ถูกกันเมื่อมีรายการจองค้าง

`fleetStatus` เป็นสถานะที่คำนวณเพิ่มสำหรับหน้าจอ ได้แก่สถานะปฏิบัติงานข้างต้น, `RESERVED`, `IN_USE`, `OVERDUE`, `UNASSIGNED` รวมการรอ `availableFrom` หลังคืนรถ การปิดรับจองของสาขา และรายการจองที่ยังไม่สิ้นสุดจริง รถเกินกำหนดคืนไม่ถูกจัดสรรใหม่จนกว่าจะจัดการรายการเดิม

KPI ด้านบนเป็นยอดทั้งระบบ ส่วนจำนวนในแท็บ/ผลลัพธ์เป็นยอดหลังกรอง ตัวกรองและมุมมองอยู่ใน query string เพื่อให้ refresh และ Back กลับมาที่บริบทเดิม CSV ส่งออกทะเบียนที่ตรงกับตัวกรองทั้งหมด

การย้ายสาขาใช้ `PATCH /api/fleet/cars/:id` พร้อม `transfer: true` และ `transferNote` (optional, สูงสุด 1,000 ตัวอักษร) ปลายทางต้องเปิดบริการสำหรับรุ่นและผู้ให้บริการเดียวกันภายในประเทศเดียวกัน และรถต้องไม่มี `PENDING`/`APPROVED` เหตุผลถูกบันทึกในประวัติการย้ายรถ การแก้ข้อมูลรถตามปกติไม่ย้ายตำแหน่งจริงที่เกิดจากการคืนต่างสาขา

ข้อมูลตัวอย่างมีรถ **134 คันใน 28 รุ่น** กระจายครบ **13 locations** ทุกรุ่นมีอย่างน้อย 3 คัน และทุก location มีหลายคัน รุ่นในประเทศที่มีหลายสาขามีรถกระจายข้ามสาขาด้วย ทะเบียนตัวอย่างขึ้นต้น `DEMO-` และใช้ ID คงที่

สำหรับข้อมูลตัวอย่างเดิมที่มี 28 คัน ใช้คำสั่งนี้เพื่อเพิ่มเฉพาะรถและข้อเสนอที่ยังขาด โดยเก็บทะเบียน ตำแหน่ง สถานะ และรายการจองเดิมทั้งหมดไว้:

```sh
npm run prisma:seed:fleet -- --dry-run
npm run prisma:seed:fleet
```

คำสั่งนี้ไม่สร้างบัญชีหรือแก้รถเดิม รันซ้ำได้โดยไม่เพิ่มข้อมูลซ้ำ ส่วนการ seed ฐานข้อมูลใหม่ด้วย `npm run prisma:seed` จะสร้างชุดรถหลายคันนี้ด้วย
